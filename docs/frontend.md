# Frontend (static/)

**Type checking, no build step:** the JS is checked with `tsc --checkJs` via `jsconfig.json`. Run `npx tsc -p jsconfig.json` (or `deno run --allow-read --allow-env --allow-sys npm:typescript/tsc -p jsconfig.json`); it must exit clean. `types.d.ts` augments DOM interfaces with properties accessed on generically-fetched elements and declares the cross-file `window[prefix + name]` functions tsc cannot see; add to it rather than casting at call sites. `initChannelApp`'s cfg is typed as `ChannelAppConfig` (JSDoc typedef in channels.js) and excess-property-checks every platform config, so keep it in sync when adding cfg keys.

## common.js

Shared across all platform apps.

- Modal engine: `_mFiltered`, `_mRenderToolbar`, `_mSetFilter`, `_mSetSort`, `_mRenderColHdrs`, `_mRenderList`, `_mAppendVideos`, `_renderModalVideoGrid`, `_appendModalGrid`. Grid functions require explicit `thumbCellFn` / `gridThumbSrc` / `gridCellOnclick` in the cfg, no TikTok fallbacks
- `_modalShellHtml(base, closeFn, opts)` / `_modalShellScrollWiring(base)`: the one detail-modal shell (backdrop, creator-modal classes, header, toolbar, mobile filter host, list, back-to-top) plus scroll behavior. `base` prefixes every element id; opts slot in banner, extra panels, trailing markup, scroll-top handler. Used by channels.js `_modalHtml` and by tiktok.js's sound modal. New detail modals must build on this, never hand-written markup
- Modal view tabs in `_mRenderToolbar`: `cfg.viewKeys` may be an array or a function (the creator modal always appends Stats and History, plus Stories when the creator has any). History, Stories, and Stats are non-media views (`_mIsMediaView(view)` is the one predicate, add new panel views there): History keeps the search box, all three show a count line via `cfg.viewCount(view)`, and `cfg.contextFilters(view)` swaps in the History field pills (multi-select `.filter-pills.multi`, empty selection shows all) and the Stats day-range pills. Stats renders `_renderStatsCharts(host, rows)`: small-multiple single-series uPlot line charts over the daily `/stats-history` snapshots (Followers, Following, Posts on platform, Posts saved; all-null metrics skipped), themed from CSS variables at render time, with a current-value + day-delta header; under 2 points it shows an accumulating-data note. A day-range pill group in the context-filter slot (14/30/60/90, default 14, reset on view teardown) caps the window: channels.js slices the last n snapshot rows (one per day) before rendering, so shorter spans just show what exists. All cards are appended before any chart is sized: the auto-fit grid reflows on every append, so measuring per card sized chart 1 to a one-column grid and it painted across the other panels. channels.js owns the panel lifecycle (`_loadStatsPanel` / `_refreshStatsPanel` signature-gated on the SSE creators domain, `_destroyStatsPanel` on view switch and close, debounced re-render on resize)
- Media viewer modal (`#mvModal`), the one viewer for photos, multi-media posts, video playback, and stories: `openMediaViewer(slides)`, `mvStep`, `closeMediaViewer`, `openMediaViewerPending()` (instant overlay + spinner for async opens; callers check `_mvIsOpen()` after awaiting and close on failure). Slides are image URL strings or `{url, type: 'image'|'video'}`; video slides swap `#mvImg` for `#mvVid`, both inside `.mv-stage` (all viewer chrome parents to it so bars, gradient, tap zones, and seek align; radius + overflow clip live on the stage because mobile Safari drops border-radius on video). Normal videos open as a single video slide via the engine's `OpenVidModal` (the standalone `#vidModal` is gone), with `mv-single` hiding the arrows. No native video controls anywhere. Chrome: bare white play/pause and mute glyphs (`.mv-glyph`, play is action-based, mute is state-based) in the lower corners with `#mvSeek` between them (`mvSeek` / `_mvSeekSync`), synced by `_mvSync` off the video's inline event attributes; mute is sticky across slides and reset on close; manual toggles flash via `_mvFlash` (autoplay never flashes). `.mv-topbar` (top right, never shifts the media) holds Download (`mvDownloadCurrent`, uses `slide.name` when present), Link (`mvOpenLink`, disabled when the slide has none, hidden in story mode since stories have no permanent URL), the story-only slots, and close, all `.mv-btn`. Slides opened from a video row also carry `info` (pre-rendered details HTML from the engine's `_mvInfoFor(v)`: description plus `_hgRow` field rows, fields render only when populated); `_mvShowSlide` fills `#mvInfo` and toggles `mv-has-info` on the modal. Desktop shows the panel as a card right of the media; mobile hides it behind a topbar info button (`mvToggleInfo` toggles `mv-info-open`, overlay card below the topbar). The panel width is the `--mv-info-w` token on `.mv-inner` and `.mv-has-info` subtracts it (plus the row gap) from the media's own `max-width` caps: the flex row centers as one unit, so widescreen media sized to the full cap pushed the panel off the right edge. Stories and bare URL slides carry no info, so panel and button never show there. `openStoryViewer(slides)` opens the same modal in story mode: per-slide progress bars (5 s per image, duration per video, error advances), 20/60/20 tap zones (sides step, back on the first restarts it, center toggles pause with a flash; `_storyPause` / `_storyResume` freeze and resume the bar and advance timer, armed via `_storyArm` so remaining time is readable), no button chrome or seek bar, auto-close after the last slide. closeMediaViewer tears story mode down fully
- `setHdrAuth(platform, present, label)`: platform apps report auth state; the header pill shows the active tab's and hides for platforms that never report (YouTube)
- `_platformDiagRun(platform, idPrefix)` / `_platformDiagCopy(idPrefix)`: shared diagnostics pane logic
- `_attachSentinel(listEl, obsHolder, callback)`: IntersectionObserver scroll sentinel. Its 1px div carries `.list-sentinel` so `_reconcileRows` leaves it alone
- `_reconcileRows(el, rows, onCreate?)`: keyed in-place row diff for a scrolling list, `rows` being `[{key, html, attrs}]` in display order (`html` is the row's inner markup, `attrs` the per-row wrapper attributes, static ones go in `onCreate`). Rows whose key and html are unchanged are not touched; non-keyed children are dropped except `.list-sentinel`; returns true when the DOM changed. Any list that refreshes on a data change must render through this, never `innerHTML =`: rewriting a container empties it, so the browser clamps `scrollTop` to 0 and every sentinel-loaded page is destroyed, and the dashboard lists refresh every couple of seconds while a loop runs
- `_attachEdgeFade(el)`: toggles fade-l/fade-r mask classes on an element carrying `.edge-fade` (a horizontally scrollable row) and returns its update fn for callers that re-render. Used by the catalog filter bar, the Recent activity header filter row, the settings section row (`.settings-sub-tabs`), and the modal toolbar (`_mEnsureToolbarFade`). Add `.edge-fade` and call this to reuse it. A row of `.tab` buttons inside one also needs `margin-bottom: 0`: the scroll container clips at its padding box, so the shared -1px hairline overlap would shave the active underline to 1px

- Settings core: `_settingsRegister(id, label, sections)` (General plus every platform from `initChannelApp`), `openSettings(target, section)` (a platform id, 'general', or a legacy alias like 'backfill'/'migrate'/'auth'), `switchSettingsTarget`, `switchSettingsSection`, `closeSettings`, `toggleSettingsNav`. The nav rail lists General plus one entry per enabled platform (letter-badge icons, so new platforms need no logo); each pane is built lazily on first visit and kept in the DOM. ## channels.js

The platform app engine, shared by every platform.

- `initChannelApp(cfg)` generates the section HTML (add form, stat strip, recent activity feed, loop panel, add history panel, filter bar, creator grid, log view) into `#platform-{id}`, appends the detail modal to the body, and wires all logic in a closure. It returns a handle (`el`, `getCreators`, `loadCreators`, `openModal`, `openModalRaw`, `renderModalHeader`, `loadModalVideos`, `setModalCreator`, `getTrackingView`, ...) for platform extras
- Public functions are exported on `window` with the platform prefix (`twOpenModal`, `igTriggerNext`, `ytSaveLoopSettings`, ...) so generated onclick strings and settings markup can call them
- `initChannelApp` also registers the settings pane via `_settingsRegister`: Account, Schedule, Jobs, and Database always exist (defaults: a no-account note, `_schedulePaneHtml` + `_scheduleSettingsLoad`, the engine DB cleanup card, `initDbQueryPane`); `cfg.settings` overrides or extends them (`account`/`schedule`/`network`/`jobs`/`diag`, each `{html, onShow?, onHide?, onRender?}`; Network and Diagnostics exist only when provided; `jobs.html` is prepended before the cleanup card)
- cfg carries nouns and labels (`creatorNoun`, `subLabelCard`, `uploadDateLabel`, `loopLabel`, `loopsTitle`, `titleColLabel`, placeholders), the API base, `profileUrl(handle)`, `videoUrl(v, ch)` (the post's URL on the platform, driving the list actions Link button, the mobile row menu's Open link, and the viewer topbar, all greyed for deleted posts via `_videoLinkBtn`), plus optional hooks: `hasBanner`, `hasStories`, `uploadDateOnly` (date without time, for APIs with no time of day, i.e. YouTube), `thumbBadge(v)`, `viewKeys` / `viewVideoFilter` / `gridClassFn` / `typeIconFn` (YouTube shorts views), `fieldLabels`, `statsRows(s)`, `extraFilterGroups` (with a `test(ch, set)` predicate; `dropdown: true` renders as a multi-select, e.g. TikTok Privacy and Relation), `extraViews` (own grid/controls/`show(search)`), `extraLoopHtml` + `extraLoopLabel` + `onStatus(state)` + `statusActive(state)` + `currentActivity()` + `nextRunCandidates(state)` (a second loop block behind a panel-header toggle; the selected view persists in localStorage `{prefix}-loopView`), `addHandler(raw, addToasts)`, `videoActionBtnsFn(v)`, `recentFallback(item)` (click routing for soft-disabled creators), `onCreatorsRefetched`
- Dashboard layout: a full-width `.stat-strip` of tiles (`_renderStatGrid` into `#{prefix}StatsGrid`), then `.dash-row` with the recent activity card (fixed height, sets the row height) beside `.dash-col` holding the loop card (natural height) and the add history card (flexes into the remainder). Below 800px the row stacks and `.add-history` gets a max-height cap so its sentinel cannot page in the whole history
- Catalog filter bar (`.filter-control-group` + `.edge-fade`): all filter rows on one line, space-between; narrow windows scroll it sideways with no visible scrollbar and a faded clipped edge. The view-tab row's search box hides via visibility (not display) on the Log view so the row height never shifts; under 640px the search row is its own full-width line, so `SetTrackingView` also puts `.search-row-hidden` on it and the mobile block hides it with `display: none` instead of leaving an empty gap
- Both dashboard lists (recent activity, add history) render through `_reconcileRows`; `_listPlaceholder` and `_listSentinel` in channels.js wrap the parts around the diff (skeleton/empty/error states, and re-arming the paging sentinel only when rows actually moved, so the minute tick's label roll cannot page in another block)
- Recent activity feed: server-paginated `/recent/feed` (keyset on event ts, kind mirrors the header pills). Refreshes (SSE `changed`, else a 30 s poll) refetch page one when the JSON signature changed and stitch it onto the pages already scrolled in: page one owns the newest window, retained events older than its last one carry over, so the halves rejoin as one contiguous list. `_rfKeyOf` (kind + creator + ts + field) is the diff key, so a grouped event re-keys when it absorbs a newer post. The tail is dropped only when more new events arrived than fit in one page, which leaves a hole page one cannot cover. `_attachSentinel` pages older events in. Kind plus starred/bookmarked pills map to the endpoint params; filter switches reset `scrollTop`, render instantly from a page-one cache per combination and revalidate in the background, and hovering prefetches per-kind caches. Each `.rf-row` shows a type icon, avatar, handle, detail, and `_recentDate` time, routing clicks via `_recentOnclick` / `OpenModalWithHistory` / `OpenModal`. The per-type `/recent/*` endpoints remain but nothing in the UI calls them
- Add history panel: `/add-history` newest first in its own scroll container (the sentinel root); error rows get retry (re-POSTs `/channels` with the stored handle) and discard. Queue snapshots (SSE on the active tab, polled when hidden) drive both the add toasts (`_makeAddToasts(onAdded)`) and a top-of-history refresh, which stitches onto the scrolled-in pages the same way the feed does, keyed on the row id. Rows wrap columns in `.ah-row-content` (grid: icon, handle, status, date) with `.ah-actions` absolutely overlaid right; `_renderAddHistory` adds `.has-actions` to error rows, revealing buttons on hover and masking the content behind them (`--ah-hide` / `--ah-ramp`). Under 800px both dashboard lists start `scroll-locked` (overflow hidden so the page scrolls instead of the panel) with a corner padlock toggle (`ToggleScrollLock`); desktop ignores the class. The add bar swaps to `data-placeholder-short` under 640px. Both lists size the status column to content so the handle column expands and truncates only when needed
- Quick Access: pinned creator avatars under the add bar (`.qa-panel` / `.qa-row`; desktop left-aligned flex, mobile 5-wide grid). Pins are `channels.pinned_at` via `PATCH /channels/<id>/pin`, rendered from the creators array (signature-gated in loadCreators) using the Connected panel's slot classes and the shared `_creatorSuggest` typeahead. The panel title opens `${P}QaListModal` whose rows unpin
- Connected creators: an always-present `.conn-square` (2x2 grid of 24px slots, no title, tooltips carry labels; desktop under the avatar in `.modal-avatar-col`, mobile under the note field). Three fixed avatar slots fill from the left, the first free slot is the clickable Add placeholder, from `GET /channels/<id>/connections` (state `_modalConnections`, signature-gated `_applyConnections`, refetched on the SSE creators domain and refilled after every header re-render). An always-present manage slot (`.conn-more`, dots, or a +N overflow past 3, keeping the box width fixed) opens `${P}ConnListModal` (rows open the other creator, x unlinks), where Add and the list footer `openPrompt` a handle with a `suggest` hook (handle + display-name substring over the loaded creators, prefix first, top 8, minus self and existing) and POST it. The Escape handler closes the list modal before the creator modal
- Cards and the detail modal render the full engine domain model gated on data presence: relation/privacy pill, banned/blocked styling, lock icon, pending re-scan notice, verified badge, join date, ban countdown, bio link, following count, old handles, next-check line. Fields a platform never populates simply never show
- Card and modal layout: id line, stats row, star + Quick + Full + overflow menu, and the Added / Last checked / Last saved footer. Notes are an always-present `_noteFieldHtml` field, on desktop sharing a row with the bio link (`.modal-note-link-row`: note flexes, link at natural width with a dim italic No link placeholder), actions following as their own row (mobile keeps the note under the actions). A saved note is the same expandable xtext block as bios; an empty one is the same box chrome with a muted italic "Click to add a note". Both it and the menu's Edit note open a `multiline` `openPrompt` that PATCHes the comment and repaints the header. A missing bio renders through `_xtextPlaceholderHtml` so empty fields look alike
- Desktop modal header right side: one `.hdr-data` ledger block of three titled `.hdr-group`s (Activity: Added/Checked/Saved/Next; Platform: Followers/Following/Posts/Updates; Archive: Saved/Deleted/Restored/Stories/Storage) of `_hgRow` rows. Every row is a fixed slot so header height is constant per platform: zero or missing values render dimmed (`.tzero`) instead of despawning, the bio link line always renders, and the ban countdown sits inline in the handle row (`.modal-ban-inline`). Stories is the only per-platform difference (`cfg.hasStories`); the sound modal uses the same block. Narrow behavior: `.modal-header` is a `container-type: inline-size` container with `flex-wrap`, `.modal-header-left` has `min-width: min(520px, 100%)`, and `@container (max-width: 1112px)` wraps `.hdr-data` below the identity column full-width under a hairline. Below 640px viewport the mobile header renders instead
- The modal derives `type` ('video'|'photo') per row from `content_type` and the file extension, driving the Videos/Photos filter, thumbnail badges, and grid glyphs; photo rows open the image viewer and download under their real extension. Multi-media posts (basename starts with `{video_id}_`) open the viewer via `{p}OpenCarousel` backed by `/videos/<id>/files`
- Quick vs Full: Quick (`?mode=quick`) fetches the newest ~30 posts and skips deletion detection (absence from a partial listing proves nothing); Full is the default. On YouTube flat extraction fetches everything either way, so quick only skips the deletion pass
- Live updates: the active tab holds one EventSource on `/api/{p}/events`; the server pushes `status` and `queue` on change, so loop state, logs, and add toasts update immediately. The `changed` events (per-domain table write versions) also refresh an open creator modal: header + storage chip from the fresh creators array, a video list refetch, and the active History or Stories view, each signature-gated so unchanged data never re-renders (a re-render resets paging); the header re-render is skipped while focus is inside it. Platforms hook their own modals via `cfg.onCreatorsRefetched` (TikTok refreshes the open sound modal on the sounds and creators domains). Hidden tabs close their stream (idle streams would crowd the HTTP/1.1 connection budget) and fall back to 15 s status/queue polls, as does a browser without EventSource. Remaining polls: channels 15 s, stats 60 s, recent 30 s. The 1 s countdown tick renders the global `#nowStrip` under the tab bar (only the active platform writes it), reporting present before future: an active sleep countdown ("sleeping X, up next: Y"), then the in-progress check ("processing @handle, downloading video 2 of 5", from loop_current_channel + loop_current_stage, covering sessions and manual runs), then `cfg.currentActivity()` (TikTok: the sound loop stage), then "session running", and only when nothing runs the countdown to the nearest scheduled run
- The log console renders incrementally from the server's monotonic `log_seq`; the clear watermark persists in localStorage `{prefix}-logClearSeq`
- Profile history diffs old against new values (current profile value for the newest entry, the next-newer entry's old value otherwise) with status labels for `account_status` / `privacy_status`
- Polling suppression: `loadStatus()` calls `updateRunStates()` instead of rebuilding cards. `loadCreators()` skips the grid rebuild via a JSON signature check, but rebuilds once a minute so relative timestamps stay current. Prevents hover and avatar flicker. Search is debounced 150 ms in `OnSearch`
- The creator grid shows `.skeleton-card` shimmer until the first fetch lands; `renderCreators` adds a one-shot `grid-anim` class for the staggered entrance (poll rebuilds never replay it)

## style.css

CSS variables in `:root` define the design system (colors, radii, shadows, typography); per-platform themes override a subset when the active tab changes. The `theme-{platform}` class lives on `body`, not `.app`: dialogs and toasts are appended to body, so a theme scoped to `.app` left every modal on the neutral `:root` accent.
- Every platform overrides `--accent` (TikTok fuchsia, YouTube red, Instagram magenta, Twitter blue, OnlyFans `#00aff0`); the `:root` blue is the neutral chrome accent. `--on-accent` is only for text/glyphs on SOLID accent fills; translucent tints keep `--text`
- Accent-derived tints (hover borders, glows, the `.app::before` ambient glow, panel title dots, avatar rings) use `color-mix(in srgb, var(--accent) N%, ...)` so themes recolor them automatically. Follow that pattern instead of hardcoding rgba per theme
- Design language, "the archivist's instrument": in-page cards and panels are flat `var(--surface)` with hairline borders, no gradients; shadows belong to floating layers only (menus, popovers, dialogs, toasts), state and focus rings excepted. The whole app renders in the vendored JetBrains Mono (`static/vendor/fonts/`, OFL, weights 400-700, referenced by plain /static path); weight and color carry hierarchy. Colored pills are reserved for exceptional states (Up/Tracked are quiet text). Motion uses the `--dur-fast` / `--dur` / `--ease` tokens; the platform tabs' active underline is a `.tab-glider` placed by `_placeTabGlider`. Small dialogs share `.confirm-card` (plus `.wide`); `.dd` and `.m-dd` share one 28px pill spec, and filter-bar and toolbar controls sit at the same height
- The page background lives on `html` (body transparent) so the fixed z-index -1 `.app::before` glow paints above it; the tab bar plus `#nowStrip` pin as one sticky `.top-chrome` with backdrop blur
- Radius tokens: `--radius-lg` (cards, panels, modals), `--radius` (buttons, media), `--radius-sm` (small controls), `--radius-pill`. Extra colors: `--gold` (star), `--purple` (log profile lines), `--blue` (fixed cross-platform blue for the feed's changed kind, never varies with theme), `--orange` (missing states). Never hardcode radii or these colors
- Tabs use the shared `.tab` underline (accent text + 2px accent bottom border). Top platform tabs also carry an identity dot from the `:root` `--p-{platform}` tokens (the same source the theme `--accent` overrides reference; no token falls back to muted grey), and `setHdrStatus` toggles `.loop-active` to pulse it while that loop runs, so activity is visible from any tab. When a tab is a `<button>`, set `border-radius:0`: the base button radius turns a bottom-border underline into a curved line. Full-width (`flex:1`) vs left-aligned is a layout choice, not a style rule. Segmented choices that are not top-level nav use `.filter-pills`
- Settings markup uses shared utility classes instead of repeated inline styles: `.settings-label`, `.settings-note`, `.settings-group`, `.settings-subtitle`, `.hr-divider`, `.btn-sm`, `.diag-copy-btn`, `.hdr-link`, `.version-tag`, `.snav-badge` (the nav rail letter circle). Inline `style="display:none"` toggles stay inline because JS flips `el.style.display` directly

## Overlays: native `<dialog>` and popovers

Overlays are native `<dialog>` opened with `showModal()` through `_dlgOpen` / `_dlgClose` / `_dlgIsOpen` / `_dlgWire` in common.js: Escape, focus containment and restore, backdrop-click detection (the dialog element is the full-viewport backdrop), and stacking all come from the top layer, so there is no Escape priority chain and no z-index ladder. Close cleanup lives in a `_dlgWire(id, onClose)` listener so it runs on every close path including native Escape. `_dlgOpen` pushes onto `_dlgOpenStack` and both close paths call `_dlgDrop`, which keeps that stack and the toast host in step. The dim background stays on the dialog element, but the page blur belongs on `::backdrop`: backdrop-filter on the dialog element composites the dialog's own content into the blur layer, and the fractionally sized flex-centered modal then rasterizes all its text off the pixel grid (blurry text on desktop).

Dropdown menus (`.dd`, `.m-dd`) and the card action menu are popovers (`_menuOpenAt` positions them by the trigger with viewport clamping; light dismiss and Escape are native; `_menuFocus` adds arrow-key navigation). The old portal-to-body for `.dd` is gone since the top layer escapes clipping ancestors. The toast container is a manual popover re-promoted on every toast and `_dlgOpen`, **and** reparented by `_hostToasts` onto the innermost open dialog: the top layer gets toasts painted above a modal but not clickable over it, since a modal `<dialog>` makes everything outside its own subtree inert. See the gotcha in [gotchas.md](gotchas.md) before moving any overlay that must work above a modal. Popover calls go through `_popShow` / `_popHide` / `_popIsOpen`: on browsers without the Popover API (iOS/Safari 16) style.css hides `[popover]` behind `@supports not selector(:popover-open)` and the wrappers emulate display toggling, the beforetoggle/toggle events, and light dismiss. Never call showPopover/hidePopover directly.

## Misc rules

- **Keyboard:** slash focuses the active platform's search box (ignored while typing or with a modal open); creator cards are focusable and open with Enter or Space; global focus-visible ring on buttons, links, and role=button
- **Card click target:** `onclick="if(!event.target.closest('button'))openModal(...)"` on the card div. Better than `stopPropagation()`: disabled buttons do not fire onclick, so clicks on disabled areas bubble to the parent
- **URL state:** the active tab is reflected in the URL hash (`#tiktok`); tab init reads it on load
- **Password manager suppression:** the creator username/URL input is a `contenteditable` div, not `<input>`, which Safari and Chrome password managers ignore. JS reads `el.textContent`; paste goes through `execCommand('insertText')`
- **Page grids and min-content:** see the layout trap in [gotchas.md](gotchas.md)
